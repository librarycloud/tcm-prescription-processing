# 全系统生产部署与运维手册 (Production Deployment & Operations Manual)

> [!IMPORTANT]
> **适用对象**：系统运维工程师、DevOps、技术实施人员  
> **覆盖范围**：Linux 云服务器准备、Node.js 24 后端、MariaDB、Redis、Nginx 反代与 SSL、前端构建托管、E6Sync 现场部署、数据库定时备份与健康监控。

## 1. 部署架构总览

全系统在生产环境下推荐采用“**单云端服务中心 + 多端统一接入 + 门店现场边缘同步**”的标准拓扑：

```mermaid
flowchart TD
    subgraph Clients["前端与移动端用户层"]
        WebAdmin["Web 管理端 PC<br>(门店/仓库运营人员)"]

        MiniProg["微信小程序 双端<br>(微信生态 / 移动打卡)"]
        AndroidApp["Android 药房助手<br>(手持 PDA / 盘点机)"]
    end

    subgraph Gateway["边缘接入与安全网关"]
```

## 2. 云服务器硬件与系统环境基准

### 2.1 推荐硬件配置

| 规模等级 | 门店数量 | 日处方量 | 推荐配置 (云服务器 ECS/CVM) |
|---|---|---|---|
| **标准型 (单机单实例)** | 1 ~ 5 家 | < 2,000 单 | **4 核 CPU / 8GB 内存 / 100GB SSD / 5Mbps+ 带宽** |
| **增强型 (高并发连锁)** | 5 ~ 20 家 | 2,000 ~ 10,000 单 | **8 核 CPU / 16GB 内存 / 200GB SSD / 10Mbps+ 带宽** |

### 2.2 推荐操作系统
- **首选**：Ubuntu 24.04 LTS / Ubuntu 22.04 LTS
- **备选**：Debian 12 / Rocky Linux 9 / AlmaLinux 9 / CentOS 7.9+（需升级内核）

## 3. 基础依赖环境安装与调优 (Ubuntu 示例)

### 3.1 系统基础更新与工具链
```bash
sudo apt-get update && sudo apt-get upgrade -y
sudo apt-get install -y curl wget git build-essential nginx certbot python3-certbot-nginx
```

### 3.2 安装 Node.js 24 LTS (NodeSource 官方源)
```bash
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v # 确认输出 v24.x.x
npm -v

# 安装 PM2 全局进程管理工具
sudo npm install -g pm2
```

### 3.3 安装与配置 MariaDB 10.6+
```bash
sudo apt-get install -y mariadb-server mariadb-client
sudo systemctl enable mariadb
sudo systemctl start mariadb

# 安全初始化
sudo mysql_secure_installation
```

#### 字符集与高并发参数优化 (`/etc/mysql/mariadb.conf.d/50-server.cnf`):
```ini
[mysqld]
character-set-server = utf8mb4
collation-server     = utf8mb4_unicode_ci
max_connections      = 500
wait_timeout         = 600
interactive_timeout  = 600
innodb_buffer_pool_size = 4G # 建议为系统空闲内存的 50%~60%
innodb_log_file_size    = 512M
```
重启生效：
```bash
sudo systemctl restart mariadb
```

#### 创建业务专用用户与数据库：
```sql
CREATE DATABASE tcm_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'tcm_user'@'127.0.0.1' IDENTIFIED BY 'StrongDatabasePassword2026!';
GRANT ALL PRIVILEGES ON tcm_db.* TO 'tcm_user'@'127.0.0.1';
FLUSH PRIVILEGES;
```

### 3.4 安装与配置 Redis
```bash
sudo apt-get install -y redis-server
sudo systemctl enable redis-server
```
编辑 `/etc/redis/redis.conf`，设置密码和绑定本地：
```ini
bind 127.0.0.1 ::1
protected-mode yes
requirepass StrongRedisPassword2026!
maxmemory 1gb
maxmemory-policy allkeys-lru
```
重启生效：
```bash
sudo systemctl restart redis-server
```

## 4. 后端 API 服务部署

### 4.1 代码克隆与安装
```bash
# 推荐部署目录
sudo mkdir -p /var/www/tcm
sudo chown -R $USER:$USER /var/www/tcm
cd /var/www/tcm

git clone https://github.com/librarycloud/tcm-prescription-processing.git .
cd backend
npm install --omit=dev
```

### 4.2 配置生产环境变量 (`backend/.env`)
```bash
cp .env.example .env
nano .env
```

```env
# Redis

# JWT 鉴权密钥 (使用 openssl rand -hex 32 生成)

JWT_EXPIRES_IN="7d"

# AES-256-GCM 32字节加解密主密钥 (使用 openssl rand -hex 32 生成)
ENCRYPTION_KEY="0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"

# 持久化目录与最大上传大小 (确保目录已创建且有写权限)
```

### 4.3 数据库迁移与初始化
```bash
# 1. 安全应用全部数据库迁移
npm run prisma:deploy

# 2. 生成强类型客户端
npm run prisma:generate

# 3. 首次部署初始化管理员账号与预设门店 (账密: 13800000000 / 123456)
npm run prisma:seed
```

> [!WARNING]
> 登录系统后，请**立即**在个人中心修改超级管理员的初始密码，切勿使用默认密码运行！

### 4.4 配置持久化目录权限
```bash
mkdir -p /var/www/tcm/backend/uploads
mkdir -p /var/www/tcm/backend/data/releases
chmod -R 755 /var/www/tcm/backend/uploads
```

### 4.5 使用 PM2 启动与自启管理
在 `backend/` 目录下创建 `ecosystem.config.cjs`：
```javascript
module.exports = {
  apps: [
    {
      name: 'tcm-backend',
      script: 'src/app.js',
      instances: 'max',       // 根据 CPU 核心数启动多实例集群
      exec_mode: 'cluster',
      env_production: {
        NODE_ENV: 'production'
      },
      max_memory_restart: '1G',
      autorestart: true,
      error_file: './logs/pm2-err.log',
      out_file: './logs/pm2-out.log',
      merge_logs: true,
      time: true
    }
  ]
};
```

启动并设置开机自启：
```bash
pm2 start ecosystem.config.cjs --env production
pm2 save
pm2 startup # 根据提示复制执行生成的 sudo env PATH=... 命令
```

## 6. Nginx 反向代理与 HTTPS SSL 配置

创建虚拟主机配置文件 `/etc/nginx/sites-available/tcm.conf`：

```nginx
# HTTP 自动重定向至 HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name tcm.yourdomain.com;
    return 301 https://$host$request_uri;
}

# 核心 HTTPS 服务站点
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name tcm.yourdomain.com;

    # SSL 证书配置 (Certbot 会自动维护)
    ssl_certificate /etc/letsencrypt/live/tcm.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tcm.yourdomain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    # 全局最大上传限制 (处方高清图、调配视频)
    client_max_body_size 50M;

    # Gzip 压缩优化
    gzip on;
    gzip_min_length 1k;
    gzip_buffers 4 16k;
    gzip_http_version 1.1;
    gzip_comp_level 6;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript image/svg+xml;
    gzip_vary on;

    # 1. Web 用户端 (根路径: https://tcm.yourdomain.com/)
    location / {
        root /var/www/tcm/web-user/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # 2. Web 管理端 (后台: https://tcm.yourdomain.com/admin/)
    location /admin {
        alias /var/www/tcm/web-admin/dist;
        index index.html;
        try_files $uri $uri/ /admin/index.html;
    }

    # 3. 后端 Fastify API 接口反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:3000/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
        proxy_send_timeout 60s;
    }

    # 4. 静态附件与处方照片访问池 (带防盗链与长缓存)
    location /uploads/ {
        alias /var/www/tcm/backend/uploads/;
        expires 30d;
        add_header Cache-Control "public, no-transform";
        access_log off;
    }

    # 5. Android APK 分发直链与更新检查
    location /app/ {
        proxy_pass http://127.0.0.1:3000/app/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

激活并验证配置：
```bash
sudo ln -sf /etc/nginx/sites-available/tcm.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 申请免费 SSL 证书 (Let's Encrypt)：
```bash

```

## 8. 日常自动化运维与数据库灾备

### 8.1 MariaDB 每日全量自动备份脚本

创建 `/opt/scripts/backup-tcm-db.sh`：
```bash
#!/bin/bash
BACKUP_DIR="/var/backups/tcm_database"
DATE=$(date +'%Y%m%d_%H%M%S')
DB_USER="tcm_user"
DB_PASS="StrongDatabasePassword2026!"
DB_NAME="tcm_db"
KEEP_DAYS=14

mkdir -p $BACKUP_DIR

# 执行压缩备份
mysqldump -u$DB_USER -p$DB_PASS --single-transaction --quick $DB_NAME | gzip > "$BACKUP_DIR/${DB_NAME}_$DATE.sql.gz"

# 清理超过 14 天的旧备份
find $BACKUP_DIR -name "*.sql.gz" -mtime +$KEEP_DAYS -delete

echo "[$DATE] Database backup successfully completed."
```

赋予执行权限并加入 Crontab：
```bash
chmod +x /opt/scripts/backup-tcm-db.sh
sudo crontab -e
```
添加每天凌晨 02:30 执行备份：
```cron
30 2 * * * /opt/scripts/backup-tcm-db.sh >> /var/log/tcm_backup.log 2>&1
```

### 8.2 PM2 日志自动切割
防止应用运行数月后产生数十吉字节的大日志文件：
```bash
pm2 install pm2-logrotate
pm2 set pm2-logrotate:max_size 50M
pm2 set pm2-logrotate:retain 10
pm2 set pm2-logrotate:compress true
```

## 9. 应急回滚与灾难恢复 SOP

### 场景：代码发版后出现重大 Bug 需要紧急回滚
```bash
cd /var/www/tcm
# 1. 切换至上一个稳定 Tag 或 Commit
git checkout <stable_commit_id>

# 2. 重新编译前端
cd web-admin && npm run build
cd ../web-user && npm run build

# 3. 重新装载后端服务
cd ../backend
npm install --omit=dev
npm run prisma:generate
pm2 reload tcm-backend
```

### 场景：数据库误删需要全量恢复
```bash
# 解压备份文件并恢复到数据库
gunzip < /var/backups/tcm_database/tcm_db_20260905_023000.sql.gz | mysql -utcm_user -pStrongDatabasePassword2026! tcm_db
```
